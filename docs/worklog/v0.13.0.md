# v0.13.0 — the handoff

2026-08-29. The release that removed this repository's ability to operate
itself, and wrote down what that ability knew.

This file replaces what would have been `knowledge/ledger/0014`. It is the
first entry in a new series and the series has a different shape: worklogs
record a release, they do not carry threads forward, and nothing gates them.

## Why

PSGraphRender ran a resident agentic workflow from v0.1.0 to v0.12.0: a
`CLAUDE.md` read in full before every session, five skills under `.claude/`, a
thread ledger under `knowledge/ledger/`, and `tools/threads.ps1` compiling the
threads into `docs/threads.json`. It worked — thirteen entries, 112 threads
raised, 71 retired — and it is being removed because the repository is now one
of five governed from a harness project rather than a repository that governs
itself. Two processes reading two sets of instructions about the same commit is
one process too many, and the in-repo one was the one with no reader left.

The removal is deliberate and it is a loss. What follows is what was done about
the loss.

## What was stripped

`CLAUDE.md`, `.claude/` entire, `docs/threads.json`, `tools/threads.ps1`,
`tests/Ledger.Tests.ps1`, `tests/Instructions.Tests.ps1`.

The suite went from 127 passing / 15 not-run to 122 passing / 9 not-run. That
delta is exactly `Instructions.Tests.ps1`'s five tests and `Ledger.Tests.ps1`'s
six `PreTag` tests. Coverage was 81.75% before and after; the browser gate ran
six pages across two backends and three fixtures before and after. **No
assertion about the renderer changed.** Removing a reference to deleted
machinery is not weakening an assertion, and nothing else was touched.

`tests/Instructions.Tests.ps1` enforced two rules worth naming as they go: a
byte ceiling on the always-loaded tier, which has no tier left to measure, and
**"no instruction file may cause a push by being followed"**, which has no
instruction files left to scan but is still true. It is restated in
`docs/HANDOFF.md`, unenforced. That is a real reduction in guarantee and it is
recorded rather than glossed.

## What was kept, and where it went

`knowledge/ledger/` became `docs/ledger-archive/`, moved with `git mv` so the
history follows the files. Thirteen entries, unchanged, plus a README saying
they are a record and not a process.

Everything durable in `CLAUDE.md` and the five skills was extracted before the
delete and folded into `docs/HANDOFF.md`: the core node/edge constraint and the
six forbidden words with the six surfaces they apply to; the producer-agnostic
boundary; the contract's own version policy and the falsifiable test for the
schema ("if a Python or Go producer would have to reshape its data to satisfy
it, the schema is wrong"); the four config files stated by what they must
*never* hold; the registry rule; gravity as a principle rather than a mechanism;
the commit and release conventions; and the gate-falsifiability method, which
was the single largest orphan — `falsifiab` returned zero hits anywhere under
`docs/`, and the documentation recorded instances of the practice without ever
recording the rule.

Seventeen threads were still open. They are in `docs/HANDOFF.md` as a table,
one line each, with their full raising text still in the archive under the entry
whose number prefixes the id. Four of the seventeen are about the thread
machinery itself and are moot now; they are listed anyway so that a reader
counting seventeen against the archive finds seventeen.

## What was added

`tools/Update-Vendor.ps1`. The vendor manifests have carried a prose procedure
since v0.5.0 — fetch the URL, compute this expression, compare before replacing
— and prose is not a tool. The tool does exactly that, plus the two refusals
that matter: a failed download changes nothing, and a `-PinVersion` whose bytes
hash to the value already recorded is refused, because recording a new version
number against unchanged bytes would make the manifest state something false
about the file next to it.

Two properties worth stating. It rewrites `vendor.psd1` **textually** — three
property lines inside the matched entry block — because the file's long comment
header is most of its value and a round trip through
`Import-PowerShellDataFile` would delete it. And after copying, it re-reads the
file from disk and re-hashes it before the manifest is allowed to claim that
hash: the manifest may only record a digest that has been observed on the file
sitting beside it.

It was falsified rather than read. One byte flipped in a scratch copy →
`-Verify` exits 1 naming exactly that file and leaving the other green. A
manifest entry pointed at a 404 → `-Update` refuses naming the entry, and the
vendored file and the manifest are both left as they were. An untouched copy →
green. The tamper probes assert the file actually changed before the check runs,
which caught a first attempt where a path was mangled between shells, nothing
was modified, and the green was meaningless.

## What could not be verified

- **`Start-ThreadJob`'s absence has never been observed.** The tool fans per-file
  work out over ThreadJob and reports a sequential fallback if it is missing.
  PowerShell 7.6 ships the module in `$PSHOME\Modules` and it could not be
  removed from the module path, so the *detection* has never returned false on
  a real machine. The fallback *branch* was exercised by forcing the flag, and
  doing so found a genuine bug in it — array-subexpression syntax where
  splatting was intended, which mislabelled every result.
- **The `PreTag` gate's new documentation describes three `Describe` blocks that
  were read, not run against a broken repository.** The gate itself is
  unchanged and still green; what changed is only the prose about it.
- **Nothing checks that `docs/HANDOFF.md` stays true.** The file it replaces had
  a test enforcing that every path it named existed. Nothing enforces that here,
  and `docs/HANDOFF.md` names a dozen paths.
- **`docs/contract.md` still says the contract is 1.0.0 and the module 0.3.0.**
  Both halves are stale — the contract is 1.1.0 and the module is 0.13.0. It was
  left alone deliberately: the schema was out of scope this release and a
  contract doc is not machinery. It is wrong today and someone should fix it.
