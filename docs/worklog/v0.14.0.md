# v0.14.0 — a node link becomes a decision

2026-09-04. The first release since the handoff, and the first change to `src/`
under harness operation. Pass 0047.

## Why

A node link could only ever be an editor scheme. `vsCodeUriFor` hardcoded
`vscode://file/`, `NODE_ACTIONS` bound to it, and no setting named an
alternative. Pass 0043 found this while building `examples/links/`: it wanted a
report attached to a pull request, where the reader has no clone and the useful
destination is the file on the forge, and it could not have one. It filed the
item **large** and stopped, which was right.

So the example shipped with an inert placeholder `rootPath` and a paragraph
explaining why its links do not work. That paragraph was the backlog item's
receipt.

## What it is

`LinkMode`, an Enum of `editor`, `hrefTemplate` and `none`, defaulting to
`editor`. `LinkHrefTemplate` beside it. Both declared as data in
`Config/settings.schema.psd1`, the same way every other setting is declared —
no new validator type, because `Enum` and `String` already existed.

No contract change. Every token — `{relativePath}`, `{path}`, `{id}`,
`{label}`, `{line}` — resolves from a field the view model already carries.
That was checked before any code was written, because a contract change is
cross-repository and belongs to a decision rather than to a pass's momentum.

## The decision that shaped everything else

The mode is resolved when the document is **assembled**, not by a branch in the
browser.

Runtime resolution was the cheaper design and it was rejected. A report is one
self-contained file that gets forwarded, so a runtime branch would leave every
other mode's code sitting in the document — inert, but present, and readable by
anyone the file reaches. `none` has to mean the scheme construction is not in
the artifact. `SlotsBySetting` in `templateset.psd1` picks which files fill the
node-link slots, and a shipped report carries one mode's code and not three.

## What the no-regression control cost, and bought

The acceptance for `editor` mode was that a rendered document stays
byte-identical to v0.13.0's for the same payload. That is a strong claim and it
constrained the refactor completely: code could not **move** within the
assembled document, only into files re-inserted where it already sat.

So `editor-link.js` became `link/common.js` plus `link/editor.js`, split at the
blank line between `isEmbeddedContext` and `vsCodeUriFor` — `common.js` keeps a
trailing newline on purpose, because that newline *is* the blank line, and the
join reproduces the original because of it. The two editor menu entries, the
selection action and the diagnostics row became slots filled at the positions
they already occupied, rather than a `LINK_NODE_ACTIONS.concat(...)` in
`menu.js`, which would have been the obvious design and would have changed
bytes that had no business changing.

The split was carved programmatically and asserted lossless rather than
retyped. `tests/LinkMode.Tests.ps1` builds a fresh clone at the previous
release, renders the same payload in a child process, and compares. It is green
before and after; its red capability is demonstrated against a scratch render
with the default flipped.

The cost is a directory of small files, several of which are fragments that do
not parse alone. The purchase is that a behaviour-preserving refactor was
*proved* behaviour-preserving, byte for byte, rather than argued to be.

## Three gaps this opened, all closed here

**Slot fragments do not parse alone.** `node --check` reported seven
SyntaxErrors about the check rather than about the files. `FragmentSlots`
declares which slots take fragments and `LintJavaScript` wraps them first —
declared by slot, not by listing paths, so a fourth mode's parts arrive checked
instead of arriving unchecked and looking checked.

**`Module.Quality.Tests.ps1` walked `Slots` only.** Two of the three modes'
files would have shipped unasserted. It walks both now.

**`{relativePath}` escaped its own separators.** `encodeURIComponent` over a
whole path gives `src%2FPublic%2FWidget.ps1`, which is correct for a query
value and useless for a `/blob/main/{relativePath}` URL. Each token escapes for
its own shape now. This was found by the browser probe, on the example this
release adds — the feature would have shipped broken in exactly the case it was
built for, and the thing that caught it was insisting a link is not a link
until a browser resolves it.

## What is new to run

`./build.ps1 -Task TestLinkMode` opens each mode in Chromium, right-clicks a
node, and reads the href off the menu. It is separate from `TestBrowser` on
purpose: that task asks whether a page came alive, this one asks whether the
links a live page offers are the ones configuration asked for.

Neither reaches into the page. `cy` and the link resolvers live inside the
bootstrap IIFE, and exposing them for a test would put a global into every
shipped report — which the byte-identity control would then catch, correctly,
as a change to the document. So the probe right-clicks like a person.
